MULTI-ZONE IS MANDATORY
=======================
ORCA must support one or many zones. Use a stable zoneId for every zone.
Never rely only on array position. Never allow Zone 1 data to appear under
Zone 2.

sources, or AI results. Missing data must be represented explicitly.

GIT SAFETY

AGENT RESPONSIBILITIES
======================

1. weather_agent.py
   Interpret supplied weather evidence:
   - temperature;
   - wind speed/direction;
   - precipitation;
   - visibility;
   - pressure;
   - forecast/observation status;
   - timestamps;
   - quality.
   Return structured assessment and evidence.

2. ocean_agent.py
   Interpret supplied marine evidence:
   - wave height;
   - wave period/direction;
   - current;
   - tide;
   - SST;
   - sea state;
   - depth where available.
   Do not invent variables that the input does not contain.

3. ecosystem_agent.py
   Interpret supplied ecosystem/environmental evidence:
   - ecosystem condition;
   - sensitivity;
   - biodiversity indicators;
   - chlorophyll/productivity when available;
   - habitat;
   - protected/sensitive areas;
   - ecological constraints.
   Missing data remains missing.

4. risk_agent.py
   Combine evidence from domain agents and estimate structured risk.
   It must consume evidence; it must not invent raw measurements.
   Risk should be traceable to supplied factors.

5. decision_agent.py
   Produce the final recommendation.
   For multiple zones:
   Zone 1 -> assessment
   Zone 2 -> assessment
   Zone N -> assessment
             -> compare
             -> recommendation

   Return:
   - recommendation;
   - key reasons;
   - confidence where supported;
   - evidence;
   - data-quality limitations.
   Do not expose hidden chain-of-thought.

LANGGRAPH
=========
graph/workflow.py:
Define the overall workflow.

Conceptual:
START
 -> Weather
 -> Ocean
 -> Ecosystem
 -> Risk
 -> Decision
 -> END

Multi-zone execution may be sequential or parallel where practical, but
zone identity must survive every node.

graph/state.py:
Maintain shared state such as:
- analysis_id
- request
- zones
- zone_results
- weather_results
- ocean_results
- ecosystem_results
- risk_results
- decision
- errors

Every zone result must be associated with zoneId.

graph/nodes.py:
Connect agent/tool functions to graph nodes and keep workflow.py clean.

CHAINS
======
chains/ contains domain-specific prompt/model execution when useful:
- weather_chain.py
- ocean_chain.py
- ecosystem_chain.py
- risk_chain.py
- decision_chain.py

Do not duplicate the same reasoning implementation across agent and chain
files. Keep one clear ownership path.

CHAT
====
Chat is a dedicated conversational workflow.

chat/state.py should preserve:
- conversation_id
- analysis_id
- current_zone
- history/context
- user_question
- answer

chat/router.py:
Determine the relevant context:
"What is the wind?" -> weather
"Why is Zone 2 risky?" -> risk/decision
"Compare Zone 1 and Zone 3." -> cross-zone decision context

chat/memory.py:
Manage conversation memory.

chat/context.py:
Build context from the selected analysis/zone.

chat/response.py:
Validate and format the final response.

chat/prompts.py:
Chat-specific prompt construction.

Chat MUST NOT mix data between zones.

weather_tool.py -> weather information
ocean_tool.py -> ocean information
ecosystem_tool.py -> ecosystem information
gis_tool.py -> spatial information such as classification/distances

Do not create direct uncontrolled external API access from arbitrary user input.

MULTI-ZONE REQUIREMENT
======================
Every AI request must support:
zones: []

Even one coordinate is:
zones = [Z1]

Never identify a zone only by list position.

Every agent output should preserve:
analysisId
zoneId

Example conceptual result:
{
  "zoneId": "Z2",
  "weather": {...},
  "ocean": {...},
  "ecosystem": {...},
  "risk": {...},
  "decision": {...}
}

PARTIAL FAILURE
================
If ecosystem fails for Zone 2:
- do not erase Zone 2;
- mark ecosystem unavailable/failed;
- reduce/qualify confidence if appropriate;
- let the final decision communicate the limitation;
- preserve successful weather/ocean evidence.

Do not turn a partial failure into fabricated completeness.

DATA QUALITY + PROVENANCE
=========================
Propagate:
- source;
- timestamp;
- variable;
- unit;
- forecast/observation;
- quality/status.

The AI must distinguish:
observed
forecast
missing
unavailable
stale/low-quality where supplied.

NO FABRICATION
==============
The AI must NEVER invent:
- weather measurements;
- ocean measurements;
- ecosystem measurements;
- source names;
- timestamps;
- sensor readings;
- GIS values;
- confidence as if statistically established.

If evidence is insufficient, say so in the structured output.

CONFIDENCE
==========
Confidence must reflect evidence quality and completeness.
Do not output false precision merely because the LLM can produce a number.

DECISION OUTPUT
===============
The decision should be concise and auditable through evidence:
- recommendation;
- key factors;
- confidence;
- data-quality limitations;
- zone comparison if multiple zones.

Never expose private chain-of-thought. Return summarized reasons/evidence.
